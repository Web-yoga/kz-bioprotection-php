# Рекомендации по размерам изображений (SEO + скорость)

Документ основан на текущей вёрстке проекта и типовых SEO-практиках для информационных сайтов.

## 1) Что важно в текущем проекте

- Контейнер сайта: `1140px` на широких экранах (`tailwind.config.js`, `container.screens.2xl`).
- Для контейнера используется боковой отступ (`padding`) `1rem` (и через `container`, и через `px-4` в шаблонах), поэтому реальная полезная область контента обычно в диапазоне около `1080-1140px`.
- Блоки `news` и `solutions`:
  - desktop: 2 карточки в ряд;
  - mobile (`<=639px`): 1 карточка в ряд;
  - изображения карточек: `aspect-ratio: 4 / 3`.

## 2) Общие правила SEO для изображений

- Основной формат: `WebP` (добавлять `JPG` fallback при необходимости).
- Для крупных hero/fullsreen-баннеров можно дополнительно готовить `AVIF`, если стабильна поддержка в вашем пайплайне.
- Всегда задавать `width` и `height` (или стабильный `aspect-ratio`) в HTML/CSS, чтобы избежать CLS.
- Использовать `srcset + sizes` для responsive-загрузки.
- `loading="lazy"` для изображений вне первого экрана.
- Целевой вес:
  - full-screen/hero: до `180-320 KB` (WebP);
  - контентные изображения в контейнере: до `90-180 KB`;
  - карточки (news/solutions): до `45-120 KB`.

## 3) Упрощённый стандарт (по 2 файла на каждый случай)

Ниже минимальная и практичная схема: **1 версия для desktop + 1 версия для mobile**.  
Этого достаточно для большинства информационных сайтов и даёт хороший баланс качество/скорость без сложной нарезки множества размеров.

### A. Картинка на всю ширину экрана (full-bleed / hero)

- **Назначение:** фон первого экрана, широкие промо/баннеры.
- **Рекомендуемые размеры (2 файла):**
  - Desktop: `1920x1080` (16:9);
  - Mobile: `1170x658` (горизонтальный hero) **или** `828x1472` (вертикальный, если так задумано в дизайне).

### B. Картинка на всю ширину контейнера контента

- **Назначение:** изображения внутри статьи/лендинга, широкие блоки в основном контенте.
- **Рекомендуемые размеры (2 файла):**
  - Desktop: `1200x675` (16:9);
  - Mobile: `750x422` (16:9).

### C. Картинка на половину ширины контента (news / solutions-карточки)

- **Назначение:** карточки новостей и кнопки/карточки `solutions`.
- **Из вёрстки проекта:** 2 колонки + gap `0.75rem`; изображение `4:3`.
- **Рекомендуемые размеры (2 файла, 4:3):**
  - Desktop: `560x420`;
  - Mobile: `400x300`.

### D. Картинка на одну треть контейнера (типа `oil-how-gallery__img`)

- **Назначение:** галереи/карточки в 3 колонки внутри основного контента.
- **Рекомендуемые размеры (2 файла, 4:3):**
  - Desktop: `380x285`;
  - Mobile: `320x240`.

## 4) Быстрый чеклист (без усложнений)

- Full-screen: `1920x1080` + mobile-версия.
- Container-wide: `1200x675` + `750x422`.
- Half-container (4:3): `560x420` + `400x300`.
- One-third container (4:3): `380x285` + `320x240`.

## 5) Нужно ли делать отдельные mobile-варианты 800 и 400?

Короткий ответ: **обычно можно не делать**.

- Для вашего запроса «максимально просто» достаточно двух файлов: desktop + mobile.
- Пара `800/400` для mobile — это уже микро-оптимизация (через `srcset`), а не обязательный стандарт.
- Широко принятая практика: сначала запустить с 2 версиями, потом смотреть реальные метрики (`LCP`, общий вес трафика, доля 3G/4G).
- Добавлять дополнительную градацию (`800` и `400`) имеет смысл, если:
  - мобильный трафик очень высокий;
  - на страницах много карточек подряд;
  - в Core Web Vitals видно, что картинки заметно тормозят загрузку.

## 6) Рекомендуемые качества экспорта

- `WebP quality`: обычно `72-82` для фото-контента.
- Для графики с текстом/элементами UI: `80-88`.
- Если вес высокий, сначала уменьшать размеры в пикселях, затем качество.

## 7) Финальная рекомендация для этого проекта

Используйте **только 2 версии** на каждый случай (desktop + mobile) и не усложняйте пайплайн.  
К варианту `800/400` вернуться позже, только если метрики покажут заметную выгоду.
